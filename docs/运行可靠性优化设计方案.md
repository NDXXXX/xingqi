# 运行可靠性优化设计方案

> 版本：v1.0
> 日期：2026-10-05
> 状态：第一阶段已实施

## 1. 目标

本轮只处理已经能由代码事实确认的高优先级问题：

1. `ModelConfig` 中的工具、流式与最大输出配置必须真正影响 Provider 请求。
2. 后台记忆任务在常驻进程中遇到瞬时失败后自动退避重试；处理期间到达的新任务不能因唤醒竞态而滞留。
3. QQ 反向 WebSocket 监听到非回环地址时必须配置 Access Token，避免远程客户端伪造主人事件。
4. 用双向集成测试证明本机与获准 QQ Session 共享长期记忆，同时不共享原始 transcript。

## 2. 非目标

- 不引入消息队列、Redis、向量数据库或新的后台服务。
- 不改变 Markdown 记忆正文格式和现有检索排序算法。
- 不在本轮实现 QQ 群聊、官方 Bot、发送回执或持久化事件去重。
- 不在本轮重构所有 Repository 的事务边界。
- 不修改现有 local identity，也不自动合并旧 QQ identity。

## 3. 设计

### 3.1 模型能力与输出上限

`ChatService` 继续负责选择 `ModelConfig`，但执行 Agent 时必须携带：

- `supports_tools`：为 false 时不向模型发送工具定义，也不进入工具调用循环。
- `supports_streaming`：为 false 时使用非流式 Provider 请求；若调用方要求流式展示，则把完整回复转换成一个 `chunk` 事件，保持 UI 协议不变。
- `max_output_tokens`：传给 Provider。OpenAI 兼容接口与 Anthropic 都转换为各自请求体的 `max_tokens`。

上下文裁剪仍使用同一个 `max_output_tokens`，确保预留预算与真实请求上限一致。

### 3.2 记忆任务 Worker

`kick()` 采用单 Worker + 唤醒标记：

1. Worker 未运行时创建任务。
2. Worker 正在运行时只设置唤醒标记，不创建第二个并发消费者。
3. 每轮处理后重新检查唤醒标记，覆盖“最后一次扫描后、新任务提交前后”的竞态窗口。
4. 若任务因瞬时错误回到 `pending`，Worker 使用短退避再次处理，最多仍由现有 `attempts >= 3` 规则终止。
5. 直接调用 `process_pending()` 的管理命令保持“一次调用、每个任务最多尝试一次”的语义。

### 3.3 QQ 监听安全边界

- `127.0.0.0/8`、`::1` 和 `localhost` 可在没有 Token 时监听，保持本机开发体验。
- `0.0.0.0`、`::`、局域网地址和其他非回环主机必须配置 Token，否则在启动监听前拒绝。
- 主人 QQ ID 仍在 Adapter 与 ChatService 两层校验；它不是 WebSocket 客户端鉴权的替代品。

### 3.4 跨入口记忆闭环

测试使用真实 `MemoryManager`、隔离的 Markdown vault 和内存 SQLite，不调用外部模型：

1. 本机写入核心记忆后，QQ Session 构建的上下文必须包含该记忆。
2. QQ 来源的记忆写入 local identity 后，本机 Session 必须能够召回。
3. 两个 Session 的普通消息历史保持隔离。
4. 深度召回不得读取另一 Session 的原始 transcript。

## 4. 后续阶段

以下是第一阶段结束时记录的后续项；其中发送回执、持久化去重、Provider usage 和事务缩短已在后续 AstrBot 式消息平台重构中完成：

1. QQ 显式 `active_conversation_id`，替代按时间排序推断当前 Session。
2. OneBot `message_id` 持久化去重、`echo` 回执、发送超时与重试。
3. CLI/TUI/QQ `/stop`，接通现有 `ActiveRunManager`。
4. 记录 Provider usage，并在 AgentRun/TUI 展示 token 与上下文占比。
5. 为 vault 建立轻量文件指纹，未变化时跳过全量 `rebuild_index()`。
6. 复用 HTTP 客户端，并在真实数据规模下评估数据库候选召回。

## 5. 验收标准

- 不支持流式的模型仍能在 TUI/CLI 收到正文 `chunk`。
- 不支持工具的模型请求中不包含 tools。
- 配置的 `max_output_tokens` 出现在实际 Provider 请求体中。
- 常驻 Worker 的瞬时失败无需下一条聊天触发即可恢复，三次失败后进入 `failed`。
- Worker 忙碌期间新增的任务最终会被处理。
- 非回环无 Token 的 QQ 监听配置被拒绝；回环地址保持兼容。
- 本机与 QQ 的长期记忆双向可见，原始聊天记录不串 Session。
- `uv run pytest -q`、`uv build` 和 `git diff --check` 全部通过。

## 6. 实施结果

截至 2026-10-05，第一阶段已经完成：

- Agent Runtime 根据 `supports_tools` 决定是否向模型发送工具。
- 不支持流式的模型使用非流式 Provider 请求，并向 UI 补发单个 `chunk`。
- `max_output_tokens` 已贯穿 ChatService、Agent Runtime、OpenAI 兼容 Provider 与 Anthropic Provider。
- 记忆 Worker 使用单任务唤醒协议；瞬时失败按 1 秒、5 秒退避，并继续沿用最多三次尝试的持久化限制。
- 非回环 QQ WebSocket 监听地址在没有 Access Token 时拒绝启动。
- 新增本机与 QQ 双向共享记忆集成测试，并验证原始 transcript 不跨 Session 注入。

验证结果：167 项测试通过，wheel 与 sdist 构建成功，Git whitespace 与 Markdown 本地链接检查通过。
