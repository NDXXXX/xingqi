# 星栖（Xingqi）产品需求文档 PRD V1.3｜精简版

- **产品定位**：本地优先的个人 AI Agent，支持多角色、长期记忆和工具执行。
- **使用方式**：单人使用；以本机 Web 为主要界面，兼容 CLI、QQ 等已有渠道。
- **模型方式**：用户自行选择、配置和切换模型；支持云端 API 与兼容的本地推理接口。
- **费用**：星栖免费使用，第三方模型 API 费用由用户自行承担。
- **开发基线**：在现有星栖仓库上迭代，保留现有可用功能和数据。

## 1. 产品目标

用户安装星栖、配置模型后，即可通过自然语言与 AI 交互。Agent 能根据角色设定和长期记忆持续提供个性化协助，并在授权范围内使用工具完成任务。

核心体验：**可配置模型、稳定角色、可控记忆、实际执行、本地数据。**

### 典型场景

1. 配置自己的 DeepSeek、OpenAI 或其他兼容模型接口，在聊天中切换模型。
2. 创建“编程助手”“日常伙伴”等角色，让不同角色拥有独立的人设和记忆。
3. 请 Agent 整理文件、检索资料或检查项目，并查看真实执行结果。
4. 告诉 Agent 一项长期偏好或重要安排，之后能够继续使用或纠正这段记忆。
5. 在 Web、CLI、QQ 等已有入口与同一个 Agent 核心交互。

## 2. 版本优先级

- **P0**：本版必须具备，形成可靠的本地使用闭环。
- **P1**：基础体验稳定后开发。
- **P2**：后续版本规划。

| 模块 | P0 | P1 | P2 |
| --- | --- | --- | --- |
| 启动与界面 | 本地启动、Web UI、运行状态、历史数据保留 | 安装和更新体验优化 | 桌面应用、个人服务器部署体验 |
| 模型管理 | 自定义 API Key、Base URL、模型 ID；连接测试；默认模型及聊天切换 | 按角色设置默认模型、模型能力检测 | 智能模型路由 |
| 角色 | 简单/高级创建、编辑、删除、切换；角色独立记忆 | 角色模板导入/导出 | 多角色协作、复杂世界观 |
| 聊天 | 流式回复、会话历史、重试、切换模型 | 图片理解、语音消息 | 实时语音/视频 |
| 长期记忆 | 自动提取、手动记住、查看、修改、删除、关闭；作用域隔离 | 冲突处理、来源追踪、共享偏好管理 | 更复杂的关系成长 |
| Agent 工具 | 调用已有工具、显示结果、敏感操作确认 | 工具权限细分、复杂任务编排 | 高级自主工作流 |
| Skills / MCP | 使用和管理已有能力，支持启用/停用 | 扩展安装、配置、权限管理体验 | 开放技能生态 |
| 多渠道 | 保证 Web、CLI 及现有 QQ 接入的核心能力可用 | 渠道间会话体验统一、消息推送 | 扩展更多渠道 |
| 主动交互 | — | 定时任务、提醒、用户可控的主动消息 | 角色虚拟日常 |
| 形象 | 上传/选择本地头像 | AI 生成头像 | 动态形象 |
| 数据安全 | 本地持久化、备份、密钥保护、工具授权、默认仅本机访问 | 备份恢复优化、权限增强 | 多设备同步 |

## 3. 产品页面

首版导航：**聊天｜角色｜记忆｜工具/技能｜设置**。

| 页面 | 功能 |
| --- | --- |
| 聊天 | 选择角色、选择模型、发送消息、查看历史、查看工具执行状态 |
| 角色 | 本地角色列表、简单/高级编辑、人设及头像管理 |
| 记忆 | 查看、搜索、编辑、删除记忆，开启或关闭自动记忆 |
| 工具/技能 | 查看工具、Skills、MCP 及其状态和权限，启用或停用 |
| 设置 | 模型配置与测试、默认模型、渠道配置、数据与运行状态 |

首次使用流程：**启动程序 → 打开本机 Web → 添加并测试模型 → 选择或创建角色 → 开始聊天。**

## 4. 功能需求

### F01 本地运行与数据保存（P0）

**需求**

- 在支持的操作系统上启动本地服务，通过 Web UI 使用。
- 默认监听 `127.0.0.1` 等回环地址，避免未授权的外部访问。
- 角色、聊天、模型配置和长期记忆保存在用户管理的本地数据目录。
- 展示启动状态、基础错误信息和诊断日志，日志需脱敏。

**验收**：程序重启后数据可恢复；本机可访问 Web；默认配置不会把无保护的管理接口暴露到局域网或公网。

### F02 用户自主配置与切换大模型（P0）

**需求**

- 用户可保存多组模型连接：名称、供应商、API Key、Base URL、模型 ID。
- 支持连接测试、设置全局默认模型，以及在聊天界面切换模型。
- 在兼容协议范围内接入云端或本地推理服务。
- 切换模型后保留当前角色设定、会话历史和长期记忆。
- 对密钥错误、模型不可用、余额不足、限流、超时等错误给出明确提示。
- UI 掩码显示 API Key；密钥不写入聊天记录、角色模板或日志。
- 远程模型发送对话上下文前，明确提示数据可能传输给相应供应商。

**验收**：能分别添加并使用两组受支持的模型配置；在同一会话内切换后继续聊天；日志和导出文件不泄露密钥。

### F03 角色创建与管理（P0）

**简单模式**：名称、头像、简介、性格、背景、开场白。

**高级模式**：详细人设、说话风格、世界观、初始场景、行为偏好及自定义角色指令。

**需求**

- 支持创建、编辑、删除和切换多个角色。
- 角色设定与底层大模型分离。
- 每个角色拥有独立会话及专属记忆，避免角色之间串用内容。
- 删除角色时说明对相关会话和记忆的影响。
- 后续支持通过文件导入、导出角色设定；导出模板不包含聊天、记忆或密钥。

**验收**：用户能创建两个不同角色；切换后人设和专属记忆保持独立；编辑并重启后设定仍然有效。

### F04 聊天与上下文（P0）

**需求**

- 支持流式文字对话、历史会话列表、继续聊天和失败重试。
- 在界面中显示当前角色与当前模型。
- 按当前角色加载必要的人设、会话上下文与长期记忆。
- 使用工具时清楚区分 AI 回复、工具调用状态、工具返回结果。
- 模型或工具报错时保留已发送消息，支持用户重试。

**验收**：重启后可打开历史会话；同一会话切换模型后可继续；工具失败不会显示为任务成功。

### F05 长期记忆（P0）

**需求**

- 从用户明确陈述、要求记住的信息及实际交互中提取长期记忆。
- 支持手动记住、查看、搜索、修改、删除以及关闭自动记忆。
- 记忆应包含必要的时间和来源；不把 AI 推测直接保存成事实。
- 区分角色专属记忆与可选择共享的个人偏好。
- 当新信息与旧记忆冲突时，允许更新或纠正。
- 删除记忆后，后续长期记忆检索不再返回对应记录；聊天历史单独管理。

**验收**

1. 用户提出重要安排，跨会话可以准确回忆。
2. 用户修改喜好后，旧信息不再被当作当前偏好。
3. 用户删除记忆后，后续检索不再命中该记忆。
4. 不同角色的专属记忆互不串用。
5. 重启后未删除的记忆仍可使用。

### F06 Agent 工具、Skills 与 MCP（P0 / P1）

**需求**

- 复用现有仓库可用的工具、Skills、MCP 能力。
- Agent 可在权限范围内执行真实任务，界面展示工具名称、执行状态及结果。
- 对文件删除/覆盖、命令执行、外部发送等敏感操作设置明确授权或确认。
- 用户可查看、启用和停用工具及扩展。
- 外部网页、文件、QQ 消息与技能内容不能替代用户授权。
- P1 完善权限粒度、工具配置以及复杂任务执行体验。

**验收**：至少有一类工具能完成真实任务并返回结果；无权限的敏感操作被阻止或请求确认；失败可定位原因。

### F07 多渠道（P0 / P1）

**需求**

- Web、CLI 与已有 QQ 接入复用同一套 Agent 核心和持久化数据。
- 渠道连接状态、调用失败和错误信息可诊断。
- 不同渠道可以配置不同的工具访问权限。
- P1 优化会话衔接及通过消息渠道主动发送通知。

**验收**：既有渠道通过回归测试；角色、模型配置和记忆的读取行为一致；渠道异常不会破坏数据。

### F08 主动消息与定时任务（P1）

**需求**

- 用户能创建、查看、编辑、暂停或删除提醒及定时任务。
- 支持本地时区、指定时间和发送渠道。
- 主动消息的频率、免打扰时间、启用状态由用户控制。
- 程序关闭或电脑休眠造成任务错过时，遵循一致的跳过/补发规则。

**验收**：任务按计划触发；停用后不再触发；免打扰时段不发送主动消息。

### F09 形象与多模态（P0 / P1 / P2）

**需求**

- P0：上传或选择角色静态头像，支持修改。
- P1：AI 生成头像、图片理解、语音消息。
- P2：动态形象、实时语音与视频互动。
- AI 生成和动态形象应尽量维持角色视觉一致性。

**验收**：首版角色头像可保存与展示；后续能力按对应里程碑单独验收。

## 5. 数据与安全要求

| 对象 | 规则 |
| --- | --- |
| 角色 | 保存人设与可用能力设置，可对应多个会话 |
| 会话 | 与角色关联，支持历史恢复 |
| 记忆 | 明确区分角色专属记忆与可选共享偏好 |
| 模型连接 | 保存模型参数，安全处理 API Key |
| 工具权限 | 约束工具、角色及渠道的操作权限 |
| Skills / MCP | 可配置、可停用，记录必要的运行状态 |
| 定时任务 | 保存任务内容、触发时间、状态及执行记录 |

安全要求：本地接口默认仅回环可访问；高风险操作必须经过权限检查；秘密信息脱敏；数据升级通过迁移保护已有记录；第三方模型请求仅传递完成任务所需的信息。

## 6. 交付里程碑

| 阶段 | 交付内容 |
| --- | --- |
| **M0 现状审计** | 对照现有仓库确认已完成/部分完成/未完成的功能，核查测试与数据安全 |
| **M1 核心闭环** | 本地 Web、模型配置/切换、角色、聊天、会话恢复、基础工具授权 |
| **M2 记忆与渠道** | 长期记忆管理、角色隔离、现有渠道回归、基础定时任务 |
| **M3 体验增强** | Skills/MCP 管理、角色模板、备份恢复、安装与诊断优化 |
| **M4 多模态** | 图片、语音、AI 形象、动态形象等，按实际需求逐项开发 |

里程碑按**现有代码的真实完成情况**调整，不重复实现已通过测试的功能。

## 7. 首版验收清单

- 本地服务和 Web UI 可以正常启动，重启后数据保留。
- 用户可配置、测试和切换自定义模型，API Key 得到保护。
- 支持简单/高级角色创建，至少两个角色的人设和专属记忆独立。
- 文字聊天支持流式回复、历史恢复和清楚的错误反馈。
- 记忆可自动提取、手动添加、查看、修改、删除及关闭。
- 至少一种 Agent 工具能够执行真实任务并反馈结果。
- 敏感工具操作受权限约束；执行失败有明确状态。
- Web、CLI、现有 QQ 渠道的核心功能完成回归测试。
- 默认本地网络访问安全，日志与导出文件不泄露密钥。
- 数据迁移及自动化测试通过，保留原有数据。

## 8. Codex 开发流程

1. 阅读本 PRD 和现有仓库，逐项标记**已实现 / 部分实现 / 未实现**，附代码及测试依据。
2. 根据差距生成 M0–M3 开发任务，优先修复影响核心闭环的故障。
3. 每次只实现一个可验收的功能范围，先列改动文件、数据迁移需求及测试方案。
4. 修改后运行相关测试；避免未经授权删除、重置或覆盖用户实际数据。

**第一条任务**：先完成现状审计和功能差距清单，暂不修改代码。
