# 项目功能收尾设计方案

> 版本：v1.0；日期：2026-10-08；状态：本机收尾已实施，完整人工与真实环境验收待补。范围：完成当前版本已有能力的验收、缺陷收敛、运行边界说明和发布准备；不扩展产品范围。

## 1. 背景与目标

知语已经具备 CLI/TUI、本机 Web UI、QQ OneBot、多 Provider、Agent 工具、长期记忆、角色、MCP/Skills 和运行诊断等主要能力。CI 已覆盖 Python 测试、Web 类型检查/测试/构建、CLI 帮助和 wheel 构建。

当前工作重点从继续加功能转为“收尾”：确认代码、文档和验收记录描述的是同一版本；把已知性能与真实环境验证缺口明确处理；为已有入口提供一套可重复的发布验收流程。完成后，用户能清楚知道当前版本哪些能力可用、哪些经过何种验证、哪些属于明确限制。

## 2. 收尾原则

- 以当前代码和自动化测试为实施事实来源，以 README 为用户能力说明，以本方案和专项方案记录验收状态。
- 先核对已有实现，再决定是否需要改代码。专项设计文档中的旧基线不得直接当作当前缺陷。
- 只修复可复现且属于当前范围的问题；不为“收尾”名义做全仓重构。
- 真实服务、凭据和账号不进入 CI；手工验收使用隔离数据目录，记录脱敏结果。
- 不改变本机 API 安全边界、QQ 主人和群策略、MCP 工具授权规则、记忆身份隔离及文件/数据库一致性约束。

| 领域 | 当前状态 | 收尾判断 |

| 文档 | README 与较新的收敛记录已描述主要能力；部分专项方案仍保留旧状态/旧基线 | 需要标记历史基线、更新当前状态并统一入口 |

## 4. 范围与非目标

### 4.1 本方案范围

1. 统一项目当前能力和验证状态的记录方式。
2. 完成 Web 主要路径的剩余浏览器验收；只修复验收发现的问题。
3. 评估长期记忆 10,000 条召回基准，形成明确的性能结论；必要时做有基准对照的最小优化。
4. 补齐真实 Provider、MCP、密钥存储和 Skill Git 来源的可选手工验收记录模板。
5. 更新 README、专项文档和最终发布清单。

### 4.2 非目标

- 不新增 QQ 多账号、官方 QQ Bot、语音转写/合成、Linux/NAS 部署或远程管理。
- 不建设 MCP/Skills 市场，不自动执行 Skill 脚本或安装依赖。
- 不新增身份认证、远程访问或改变本机 API 的信任边界。
- 不以模块化为目标重写 React 页面，不引入新的状态管理或请求框架。
- 不要求真实凭据或真实第三方服务作为公共 CI 依赖。
- 不把五次采样的现有基准解释为生产 SLA，也不在没有对照数据时宣称性能已经优化。

## 5. 实施阶段

### 阶段 A：整理当前状态和文档

1. 以代码、测试和最近的实施记录逐项核对专项设计文档中的状态。
2. 对已完成内容补充实施日期/验证依据；对历史问题标注“历史基线，已处理”，对未验证项写清环境边界。
3. README 仅保留用户需要了解的当前功能、限制、运行要求和安全说明；详细验收信息留在 `docs/`。
4. 在 README 文档区增加本方案链接，作为当前版本功能收尾状态的入口。

优先核对：

- `docs/未完善事项收敛设计方案.md`：旧背景与末尾实施记录并存，需要让当前摘要直接反映已完成项和剩余项。
- `docs/本机API与对话可靠性修复设计方案.md`：当前标记“待实施”，需逐项核实代码后更新状态，不凭标题判断。
- `docs/WebUI采用NapCat式React组件交互设计方案.md`：浏览器验收与拆分状态要与较新的实施记录一致。
- `docs/QQ运行闭环与渠道能力完善设计方案.md`：区分旧基线与阶段 1–5 实施结果，保留明确的后续非目标。

**完成条件：** 用户从 README 能找到当前能力和限制；专项文档不会把已实现功能描述为待实施，也不会把未验证能力写成已通过。

### 阶段 B：Web 端到端收尾验收

在临时 `ZHIYU_DATA_DIR` 中运行 `zhiyu serve`，使用合成数据及本地测试服务。覆盖以下路径：

1. 页面导航、刷新、前进/后退、总览与指定会话深链接。
2. Provider 配置与错误状态；若没有可用测试 Provider，明确记录聊天发送和取消未经过真实模型端到端验证。
3. MCP 添加、能力发现、工具授权/撤销、Resource/Prompt 展示和刷新后状态。
4. Skill 预览、安装、更新预览、取消、回收和恢复。
5. 记忆搜索、来源查看、编辑、遗忘确认及索引诊断。
6. 多 Session 切换和运行中取消；迟到事件不得更新当前非目标 Session。
7. 窄屏导航、键盘焦点顺序、弹窗关闭/焦点恢复和未保存离开行为。
8. 检查 URL、浏览器存储、DOM、控制台与 API 响应中无 Secret 明文；外部 MCP/Skill 文本以不可信文本呈现。

每项记录版本、操作步骤、预期/实际结果、是否使用隔离数据、失败类别及修复链接。不得保存 API Key、QQ 号、真实聊天内容或私有 Git 地址。

**完成条件：** 主要路径均通过，或每个失败项都有明确归因和处理结论；不能执行的真实模型场景标为“环境未提供/未验证”，不能算作通过。

### 阶段 C：记忆性能结论

1. 复核现有 `scripts/benchmark_memory_index.py` 与 2026-10-07 JSON 报告的可重复性和测量口径。
2. 至少重复运行多轮，固定数据规模、随机种子、运行环境和次数，分别记录重建、未变更同步和召回 p50/p95。
3. 检查 10,000 条召回的全量候选扫描是否影响预期单机使用体验，并记录查询候选数、结果数量和召回正确性。
4. 若决定优化，先建立可复现的性能/正确性用例，再做最小实现；对照同一数据集比较前后结果，确保召回质量、身份隔离和记忆变更恢复行为不退化。
5. 若本轮不优化，给出可接受的使用范围和后续触发条件，不以未经测量的绝对阈值做承诺。

**完成条件：** 有可复现的当前基准及结论；若代码有变化，前后结果可比较，相关记忆测试通过。

### 阶段 D：真实环境验收记录

真实环境验收是可选手工步骤，不阻塞公共 CI。用户具备相应环境时可执行：

- Provider：用专用测试配置发送一条非敏感请求，并覆盖错误凭据/服务不可用的清晰反馈。
- MCP：使用用户选定的可信 Server 检查连接、授权、撤权、停用和重连；确认 Secret 不进入读取 API、日志或诊断。
- 密钥存储：确认系统密钥存储读写行为；若环境不支持，记录具体后端与降级行为。
- Git Skill：使用用户有权访问的仓库验证预览、安装、更新预览、取消、失败回退和恢复；不执行 Skill 脚本。
- QQ：沿用 NapCat 专项验收记录；若为发布候选重新执行，使用测试账号和脱敏记录。

记录只包含服务类别、客户端/服务端版本、日期、通过项、失败类别和脱敏错误摘要。没有环境时记录“待用户环境验证”，不伪造通过结果。

### 阶段 E：版本发布门槛

发布候选版本按仓库 CI 要求执行：

```bash
uv sync --locked --dev
uv run pytest -q

npm ci --prefix web
npm --prefix web run typecheck
npm --prefix web test
npm --prefix web run build

uv run zhiyu --help
uv build

git diff --check
git status --short
```

自动检查通过后，再完成隔离数据目录下的关键手工冒烟：初始化/升级数据库、启动 Web、查看诊断、确认没有 Provider 时错误可读、确认停止命令和退出清理正常。不得对真实 `~/.zhiyu` 执行破坏性测试。

## 8. 2026-10-08 执行结果

- 已整理 README 文档入口，并修正可靠性、WebUI、QQ 和未完善事项文档的旧状态/历史基线描述。
- 已修复新会话在 Provider 选择失败时留下空会话的问题；备用 Provider 现按自身工具、流式、上下文窗口和输出上限能力执行。
- 已修复 Web 聊天结束状态更新竞态：错误时不再遗留“正在生成”，更新按请求归属和消息 ID 进行；补充 favicon 以消除本机页面的 404 控制台错误。
- 已将记忆基准合成 ID 固定，并用 25 轮生成 1,000 和 10,000 条结果。10,000 条召回 p95 为 607.27 ms，仍扫描全部候选；本轮记录为需要专项优化的性能欠项，没有声称已优化。
- 后续针对召回热点预计算查询变体与记忆正文的 n-gram 特征。25 轮复测中，10,000 条召回 p95 从 607.27 ms 降至 325.76 ms（约降低 46%）；仍是全量候选扫描，不代表更大规模性能问题已解决。详见[优化复测结果](记忆索引基准结果-优化复测-2026-10-08.json)。
- 隔离浏览器已打开全部主要页面，检查了深链接刷新、前进/后退、窄屏菜单和无 Provider 错误处理。已有记录覆盖 MCP 与 Skill 本地服务路径。真实 Provider 下聊天取消、键盘焦点顺序和未保存离开提醒仍未完成验收。
- `uv run pytest -q`：241 项通过；`npm --prefix web run typecheck`、`npm --prefix web test`（6 项）、`npm --prefix web run build`、`uv run zhiyu --help`、`uv build` 均通过。
- 真实第三方 MCP、系统密钥存储、私有 Git Skill、真实 Provider 和本轮 NapCat 复验均依赖用户环境；当前记录为未验证。
