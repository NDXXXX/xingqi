前置基线：[M0 现状审计与技术基线](M0-现状审计与技术基线.md)、[M1 本地聊天闭环](M1-本地聊天闭环技术设计.md)

## 1. 目标与范围

M2 补齐跨角色用户记忆，并验证 Web、CLI、QQ 的核心交互继续通过同一套 Agent 与数据服务：

1. 用户事实和偏好可被任一角色及默认助手使用；角色专属共同经历、剧情、关系状态保持隔离。
2. 自动记忆可关闭；用户可检查、搜索、修改和删除长期记忆。显式“记住”及手工添加在自动记忆关闭时仍有效。
3. 用户修正旧记忆后立即更新共享用户档案；删除共享记忆后所有角色都不再召回。
4. Web 多角色行为与 CLI/QQ 默认助手行为保持兼容；不在 CLI/QQ 中新增角色切换。
5. 增加 PRD F08 的基础定时提醒：本机时区、指定时间与现有消息渠道、任务启停及一致的错过处理。

不新增工具能力，不改变角色删除时保留共享用户信息的 M1 规则，不把不同角色的聊天记录或角色关系记忆互相开放。

## 2. 记忆范围与归属

| 内容 | 归属 | 可见范围 |
| --- | --- | --- |
| 用户身份、稳定偏好、用户事实、长期目标与项目 | 默认助手的本地 Identity，`Memory.shared=true` | 默认助手及所有角色 |
| 角色关系状态、角色共同经历、剧情与场景 | 当前角色 Identity，`Memory.shared=false` | 仅当前角色 |
| 其他对话原文与会话摘要 | 原 Conversation | 仅原会话 |

共享记录存入默认助手的现有 Markdown 记忆目录，并以 SQLite 的 `Memory.shared` 标记作为共享范围权威。角色 Identity 仍独立，避免更改现有记忆工作区、索引和恢复键。共享读路径只允许读取默认本地 Identity 下 `shared=true` 且 `character_id IS NULL` 的活动记忆；不能把任意渠道或角色的记录提升为全局可见。

自动提取的 `profile`、`preference`、`fact`、`goal`、`project` 归入共享用户档案；`relationship` 归当前角色。记忆巩固对共享档案按默认 Identity 运行，对角色记忆按角色 Identity 运行。显式“记住”与手工录入沿用相同分类，角色关系和剧情信息保持私有。

现有角色记忆不做批量迁移或推断共享。版本升级后旧记忆仍只在原角色可见；用户可通过默认助手手工添加需要共享的信息。Alembic 不删除既有记录。

## 3. 自动记忆控制

- 使用现有 `app_settings` 存储全局 `memory.auto_enabled`，缺省值为 `true`，无需 Schema Migration。
- 关闭后不为普通对话创建自动提取任务；显式“记住/记下来/帮我记”仍创建任务，用户手工录入仍可用。
- Web 记忆页显示当前状态并可切换；关闭只影响后续自动任务，不撤回现有记忆或正在执行的任务。
- Worker 在实际写入前复核设置和任务状态。关闭之后尚未开始的普通自动任务标记为取消；显式记忆任务不受影响。

## 4. 读写调用链

### 4.1 读取与召回

`MemoryRepository.list_visible()` 对角色请求返回该角色自有记忆和默认 Identity 下共享用户记忆。`context.py` 继续在排序前按该范围取候选；快速召回、深度召回、来源解释和召回记录均遵守相同边界。角色私有记忆不通过共享分支暴露。

Web 记忆 API 依当前 Agent 范围列出自有记忆与共享用户记忆。共享记忆的修改/删除只允许访问默认 Identity 下带共享标记的记录；文件变更使用记录自身的 `identity_id`，并继续通过 `FileMutationManager` 同步 Markdown 与 SQLite。角色页可管理共享记录，操作对所有角色即时生效。

### 4.2 写入与修正

记忆后台任务保留源 Conversation 的角色 Identity，用于检查角色清空边界和忽略的会话；模型提取之后，按第 2 节规则将可共享观察写入默认 Identity，并带 `shared=true`。来源消息仍保留可追溯关系；删除角色时来源消息按现有外键置空，共享记忆正文与索引继续保留。

记忆修正使用共享目标 Identity 执行查找、替换、冲突关系和文件 mutation。角色关系、剧情、共同经历只在当前角色 Identity 内查找和修改。

### 4.3 渠道复用

Web 角色会话继续使用角色 Identity + 共享用户档案。CLI 与 QQ 继续使用默认助手本地 Identity；QQ 群聊是否参与自动记忆仍由当前群聊安全规则决定，M2 不改变主人验证、群白名单、@ 规则、去重和 Token 机制。

## 5. 基础定时提醒

- 新增 `scheduled_tasks` 表，保存唯一 ID、内容、到期时间（UTC）、用户输入时区、目标渠道、可选 QQ 会话、启用状态、发送尝试、错误摘要及时间戳。
- 首版只支持一次性提醒；不增加重复规则、自然语言日历、角色自主创建或复杂工作流。
- 用户通过 Web 设置/查看/编辑/暂停/删除提醒；本机提醒到期后进入待处理列表，可标记完成；QQ 发送继续经过现有主人权限和目标会话校验。只允许发送给创建时记录的 QQ 主人私聊目标，群聊不主动发送。
- Runtime 启动一个可取消的轻量轮询任务，领取到期任务时使用条件更新防止并发派发。发送失败标为失败并显示原因，用户可手动重试；QQ 发送租约两分钟后可恢复，进程在 QQ 接收消息后、写回成功状态前崩溃时可能重发一次。
- 电脑关闭或程序停止时错过的一次性提醒，在下次启动后补发或显示到期，并记录触发时间；暂停或删除任务不补发。
- 所有时间存 UTC，界面按用户指定 IANA 时区显示；拒绝不存在的时区和过去时间。

## 6. Migration、错误和安全

- 共享用户记忆复用现有字段，不增加记忆 Schema；对共享标记写入 Markdown metadata，索引重建必须恢复 `shared` 值。
- 定时任务新增 Alembic Migration；Migration 不扫描或改写记忆文件、不迁移或删除旧记录。
- Worker 崩溃恢复沿用可恢复任务模式；定时发送使用一次性领取状态，避免多个运行时重复执行。
- 定时任务内容视作不可信数据，不执行其中指令；提醒仅作为原文通知发给用户，不调用模型或工具。
- API 遵循现有本机 Host、Origin、回环 peer 与写请求标记校验。QQ 派发复用现有渠道发送接口与权限限制。
- 删除角色只删除其专属记忆；共享用户记忆、共享文件和共享索引不得级联删除。

## 7. 验收

1. 在角色 A 中明确告知一项个人偏好，在角色 B 与默认助手后续会话中可正确使用；角色 A 的剧情和关系状态不会在 B 中出现。
2. 同一共享偏好被用户修正后，所有角色均使用新值；角色任一入口删除共享记忆后，后续角色召回均不再命中。
3. 自动记忆关闭后普通对话不生成记忆任务；显式要求记住与手动录入仍可保存；重启设置保留。
4. 索引重建、文件编辑同步和角色删除不会把共享记忆变成私有、重复或丢失。
5. Web、CLI、QQ 核心回归验证通过；渠道仍复用默认助手且 QQ 权限边界不变。
6. 提醒可创建、查看、编辑、暂停、删除；到期只派发一次，失败可见；程序停止期间错过后按补发规则执行；指定时区显示正确。
7. 相关 Python/前端测试、Migration 测试及 `git diff --check` 通过；不使用真实 `~/.zhiyu/` 数据做验证。
