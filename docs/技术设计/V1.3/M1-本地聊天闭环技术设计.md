## 1. 目标与范围

M1 在已有聊天、Provider 和多角色能力上补齐本机 Web 首版闭环：

1. 在聊天中为当前会话选择模型，并在后续消息和重启后保留选择。
2. 对失败的最后一轮提供重试，不重复插入用户消息。
3. 补齐 PRD P0 角色资料字段和静态头像上传。
4. 删除角色时删除其会话、角色记忆、运行记录、MCP 配置和头像文件；不得删除共享用户资料。
5. 验证已有 OpenAI 兼容 Base URL 配置可用于本机/局域网推理；不新增 Provider 协议。

本阶段不新增 Agent 工具能力，不改变 CLI/QQ 的默认助手行为，也不实现共享记忆（属于 M2）。

## 2. 已确定的行为

- 模型优先级：本轮聊天请求明确选择 > 会话已保存模型 > 角色默认模型 > 全局默认模型 > 当前 Provider 首个启用模型。
- 会话保存 Provider ID 和模型标识，避免不同 Provider 使用相同模型标识时重启后选错。
- 旧会话没有保存 Provider ID 时，继续按已有模型标识匹配；未匹配则回退角色/全局默认模型。
- 重试针对最后一条失败助手回复，重用已持久化的最后一条用户消息；重新运行前清除该用户消息之后的失败回复与运行摘要，不再次保存用户消息。
- 头像由浏览器上传至本机服务；仅接受 PNG/JPEG/WebP，最大 2 MiB。数据库仅保存随机生成的文件名，文件放在用户数据目录 `avatars/`。
- 本机/局域网 OpenAI 兼容服务可只填写自定义 Base URL、不配置 API Key；请求不发送空 Authorization 头。云端 Provider 仍可使用密钥或环境变量。
- 角色删除采用“先隔离记忆目录、再提交数据库删除、最后清理隔离目录”。启动恢复时根据角色是否仍存在来恢复或清理隔离目录。
- 本轮“角色资料”字段为名称、简介、性格、背景、说话风格、完整角色指令、开场白、世界观、初始场景、行为偏好、头像及默认模型。

## 3. 数据与迁移

新增 Alembic migration：

- `conversations.provider_id`：可空，记录最近一次实际选择的 Provider；兼容旧会话。
- `characters.opening_message`、`world_setting`、`initial_scene`、`behavior_preferences`：可空文本字段。

`characters.avatar` 保留现有字段，值改为服务端生成的头像文件名；空值表示使用默认头像。迁移不重写旧头像值；无法识别为受管文件名的旧值按普通文本保留，不尝试删除文件。

## 4. 调用链

### 4.1 会话模型选择

`ChatPage` 展示可用 Provider/模型；`useChatSession` 将 Provider ID 与模型标识附在 `/api/chat` 请求中。`ChatService._prepare()` 继续使用现有 `select_provider_model()` 校验 Provider、模型启用状态及归属。选择成功后，将最终 Provider ID 与模型标识保存在 Conversation；后续请求不携带覆盖值时沿用会话选择。

### 4.2 失败重试

失败助手消息显示“重试”。前端发送 `regenerate=true`、会话 ID 和当前模型选择。后端仅对本机 Web 会话执行此模式，由现有 `MessageRepository.prepare_regeneration()` 复用最后一条用户消息并清除其后的回复；无用户消息或会话不存在时返回明确错误。重试完成后仍遵循现有会话模型记录与记忆任务路径。

### 4.3 头像上传

新增受现有本机写请求保护的角色头像 PUT/DELETE 路由。PUT 流式读取并限制请求体大小，验证 MIME 与文件签名，写入随机文件名的临时文件后原子替换，再更新角色记录；更新失败删除新文件。替换旧头像时，数据库提交成功后再删除旧的受管文件。读取头像通过 ID 路由查库并返回 `FileResponse`，不接受客户端路径。

### 4.4 角色删除

删除前取消该角色会话中的活动运行。将 `MemoryStore.vault_dir(character_id)` 原子移动至记忆目录内的删除隔离区，然后在单个数据库事务中删除该角色相关的会话、消息、运行及步骤、会话摘要、记忆任务、记忆及派生索引/来源/嵌入/召回/巩固记录、角色 MCP 配置/运行状态、Skills 关联、Identity 和 Character。共享 Identity 与共享资料保持不变。数据库提交失败时恢复记忆目录；提交成功后清理隔离目录、受管头像文件及角色 MCP Secret 引用。启动时恢复未完成的隔离操作：仍有角色记录则还原目录，否则删除残留目录。

## 5. 错误与安全边界

- 模型列表只展示启用且 Provider 已配置的模型；服务端仍逐请求校验，不能信任前端选项。
- 首次向远程模型发送上下文前，Web 提示对应服务商及会发送的会话、角色设定和记忆范围；用户确认后，本次 Web 会话内对同一 Provider 端点不重复提示。默认云端 Provider 按远程处理；回环、私有网段及 `.local` 主机按本地推理处理；无法识别端点时保守提示。
- 模型选择失败时保留输入和历史消息，显示 Provider/模型不可用原因。
- 重试只作用于当前会话最后一轮；不接受客户端指定任意消息 ID。
- 头像接口沿用现有 Host、Origin、回环 peer 与写请求标记校验；拒绝 SVG、超限和签名不符的文件。
- 角色 ID 不能直接拼入文件路径；角色工作区路径由 `MemoryStore` 校验并生成。
- 删除期间共享 Identity 不参与级联；只清理与角色 Identity 关联的角色专属数据。
- 不记录 API Key、MCP Secret 或头像内容到日志。

## 6. 验收与验证

- 配置两个 Provider 后，可在同一 Web 会话中切换；后续消息使用所选模型，刷新/重启后仍能恢复；角色提示、消息和记忆作用域不变。
- 新旧会话均能正常选择模型；重复模型标识的 Provider 可正确恢复。
- 最后一轮失败时重试不新增用户消息；成功重试后历史中仅保留一条用户消息和一条最终助手消息。
- 创建/编辑角色可保存完整字段；头像可上传、替换、清除并在重启后展示；无效格式和超限请求被拒绝。
- 删除含会话、消息、角色记忆、MCP 配置的角色后，所有角色专属数据和文件不可再检索；其他角色、默认助手及共享用户资料保留。
- 删除中断后重启恢复到完整删除或完整保留状态，不留下可检索的孤儿数据。
- 本机或局域网 OpenAI 兼容端点可通过现有连接测试并完成聊天；无 Key 本地服务按现有空 Key 能力配置。
- 首次使用远程模型聊天前出现数据传输提示；拒绝后不会发送消息，改用本地模型无需提示。
- M1 相关 Python 测试 63 项通过；前端类型检查、9 项测试、生产构建、CLI 帮助、wheel 构建和 `git diff --check` 通过。全仓 pytest 为 270 通过、3 个 `test_agent_context.py` 上下文压缩用例失败；本次未修改对应上下文压缩实现。
