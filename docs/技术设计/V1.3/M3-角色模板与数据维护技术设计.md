## 1. 范围

盘点显示已有 Skills/MCP 管理页面、启停与生命周期操作，且 CLI 已提供基础诊断命令。本阶段不新增 Agent 工具、不扩大工具授权，也不重写已有扩展管理。M3 聚焦尚缺的两项用户能力：

1. 导出和导入可移植的角色设定模板。
2. 创建包含本地业务数据的备份，并可恢复到一个新的数据目录。

诊断继续复用现有运行总览、诊断页和 `zhiyu doctor`。备份不包含 API Key、Token、Keychain 内容、聊天以外的运行日志或缓存；恢复后跨设备的密钥引用需由用户重新配置。

## 2. 角色模板

- 使用 UTF-8 JSON 文件，格式有版本号和明确字段白名单。
- 包含名称、简介、性格、背景、说话风格、角色指令、开场白、世界观、初始场景、行为偏好和静态头像；不包含会话、消息、记忆、运行记录、渠道配置或密钥。
- 默认模型以供应商名和模型名表示。导入时仅在本机找到唯一匹配项时关联；否则清空默认模型并提示稍后设置。
- 头像以内嵌 Base64 图片数据保存，大小不超过现有 2 MiB 上限；导入复用现有图片格式与签名校验，并生成新的本地随机文件名。
- 导入始终创建新角色，不覆盖已有角色，不恢复任何记忆或历史会话。
- JSON 文件上限 4 MiB；未知版本、非法字段、过长文本和无效图片拒绝导入。

## 3. 数据备份与恢复

备份内容：SQLite 数据库一致性快照、Markdown 记忆目录和受管角色头像目录。manifest 记录格式版本、创建时间、文件相对路径、大小及 SHA-256。归档条目只能位于上述三个根路径内；拒绝符号链接、路径穿越、重复条目、超限压缩包和摘要不匹配。Keychain/环境变量秘密及本机 Skill 文件从不导出；恢复后重新配置密钥并重新安装本机 Skill。

Web 数据页和 CLI 均可创建 `.zip` 备份。恢复只解包到尚不存在的新目录，不替换当前 `ZHIYU_DATA_DIR`，先写临时目录、校验全部文件和 SQLite 完整性，再原子改名为目标目录。用户通过 `ZHIYU_DATA_DIR=<目标目录> zhiyu serve` 启动恢复实例。这样当前数据库、记忆、头像和运行进程不会被部分覆盖。

恢复后的旧版数据库仍由既有 Alembic 启动迁移升级；迁移前备份规则继续生效。配置值中的 Keychain 引用不携带密钥本身，跨机器或 Keychain 不可用时由 Provider/渠道页面提示重新配置。

## 4. 接口与调用链

- `CharacterService.export_template(id)` 仅读取角色字段和受管头像；`import_template(payload)` 校验 schema、头像和模型映射后调用现有创建/头像路径。
- API 使用 `GET /api/agents/{id}/template` 下载 JSON；`POST /api/agents/import` 接收模板并返回新角色与模型映射提示。
- 新增 `DataArchiveService` 负责打包、校验及解包；SQLite 快照使用 SQLite backup API，不复制活动中的 WAL 文件。
- `POST /api/data/backup` 返回归档下载。`zhiyu data backup [--output PATH]` 保存到本地路径；`zhiyu data restore ARCHIVE --target DIR` 只创建新目录。
- Web“数据”页提供备份下载与恢复命令说明，不通过运行中的服务覆盖数据库。
- 所有 Web 写 API 继续受现有本机 Host、Origin、回环和请求标记检查。

## 5. 验收与验证

1. 角色模板往返后设定字段相同、角色 ID 不同；会话、记忆和密钥不进入导出文件。
2. 含头像的模板可在另一角色记录上重新导入；非法 MIME、签名、超长字段、未知版本及超过大小限制的文件被拒绝。
3. 本地匹配到唯一 Provider/模型时映射默认模型；匹配缺失或歧义时安全地清空并提示。
4. 备份可恢复数据库、Markdown 记忆和头像；manifest 哈希不一致、路径穿越、ZIP 符号链接、损坏数据库及不支持的格式被拒绝。
5. 恢复目标非空时不覆盖，当前数据目录不变；正常恢复后可由现有启动迁移升级。
6. Provider/QQ 秘密不在归档任何成员或 manifest 中。
7. 相关 Python/API/CLI 与前端测试、构建和 `git diff --check` 通过；不使用真实 `~/.zhiyu/` 数据验证。

## 6. 实施记录

- 角色管理页提供 JSON 模板导入/导出。模板含角色设定、头像及可移植的默认模型标识；不含会话、记忆、运行记录或密钥。导入总是创建新角色，未能唯一匹配本机可用模型时提示用户重新选择。

- API Key/Token/Keychain 内容和本机 Skill 文件不进入归档；恢复后需重新配置密钥并重新安装本机 Skill。Skills/MCP 既有管理能力维持原样，未新增 Agent 工具。
