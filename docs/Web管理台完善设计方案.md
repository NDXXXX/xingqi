# 星栖 Web 管理台完善设计方案

> 版本：v1.0
> 日期：2026-10-06
> 状态：已实施；基础隔离浏览器冒烟已完成，完整人工场景仍待验
> 范围：完成当前项目缺口清单中的第 1 项——让用户能通过本机 WebUI 日常配置和维护 Provider、MCP 与 Skills。
> 本文记录方案与当前实施结果。自动化测试已通过，交互式页面冒烟仍需在用户环境确认。

## 1. 目标

当前 WebUI 已有运行总览、聊天、记忆浏览、Provider 添加/测试/默认模型选择、MCP 基本启停与连接操作、Skill 安装和启停等首版能力。底层应用服务和 CLI 还支持更多配置，但这些操作分散在命令行，WebUI 还不能独立完成日常维护。

本方案完成后，用户应能在 WebUI 中：

1. 查看和维护 Provider、模型、默认模型与故障切换顺序。
2. 完成 MCP Server 的配置、认证密钥设置、能力授权、连接诊断和生命周期管理。
3. 安装、预览更新、应用更新、启停、移除和恢复用户 Skill。
4. 从总览明确区分“已配置且健康”“尚未配置”“接口不可用”和“配置异常”，不因一个模块请求失败而让其他状态留在加载中。
5. 在不显示或记录 API Key、Token、环境变量 Secret 的前提下安全完成以上操作。

完成标准是日常 Provider、MCP、Skills 管理不再必须切换到 CLI。CLI 保留为高级维护、自动化和故障恢复入口。

## 2. 当前实现基线

### 2.1 Provider

当前 WebUI/API 已支持：

- 列出 Provider 及其启用模型。
- 添加 Provider、测试连接、设置默认模型。
- 查询全局默认 Provider/模型。

底层 Repository 已有 Provider 和 ModelConfig 的更新、删除、创建模型与删除模型操作；`ProviderService` 和 WebUI 还没有完整封装这些管理流程。Fallback 顺序和视觉能力目前可通过应用服务/CLI 配置，网页没有管理入口。

### 2.2 MCP

当前 WebUI/API 已支持：

- 列出状态、添加 stdio/HTTP/SSE Server、连接测试、启停、重连和移除。
- 查看已发现工具及现有授权状态。

`McpService` 已实现非 Secret 环境变量、Secret 环境变量、HTTP Header Secret、工具白名单、Resource/Prompt allowlist、状态查询和测试；这些配置尚未全部接入 WebUI。当前 UI 不应将“未配置”呈现为“服务故障”。

### 2.3 Skills

当前 WebUI/API 已支持：

- 列出、预览安装、安装、启停、移入回收站和恢复。

`SkillService` 已支持更新预览、文件变更清单、应用更新与版本备份，但网页还没有更新流程；回收站条目也没有独立列表和恢复入口。

### 2.4 当前 WebUI 公共限制

- WebUI 默认监听本机回环地址，管理写接口不得因此被扩大到远程网络。
- 管理操作应继续调用 `ProviderService`、`McpService`、`SkillService` 等应用服务，不得在 FastAPI 路由中直接改数据库或文件。
- 前端总览对各状态接口应独立容错。接口缺失/报错只能影响对应卡片，不能让模型或运行时信息一直停留在“检查中”。

## 3. 范围与非目标

### 本轮范围

- Provider 配置与模型管理。
- MCP 配置、安全变量、工具/Resource/Prompt 授权和状态诊断。
- Skills 更新、回收站、恢复和依赖/修改状态展示。
- 运行总览空状态、加载失败和部分降级状态修正。
- 为以上 Web 管理 API 增加输入验证、错误映射、访问边界和测试。

### 非目标

- 不增加新的 Provider 协议、模型市场或自动探测所有可用模型的能力。
- 不实现 MCP OAuth 浏览器授权；HTTP MCP 继续使用现有静态 Bearer/Header Secret 能力。
- 不实现 MCP/Skills 在线市场、远程任意安装器、Skill 脚本执行或依赖自动安装。
- 不做多用户、远程管理后台、组织权限或租户隔离。
- 不改变 NapCat/QQ 运行链路、Agent 工具能力、角色系统和长期记忆机制。
- 不为当前模型、MCP、Skills 表新增重复的 Web 专用数据模型；如无代码核对后确认的必要，不新增数据库迁移。

## 4. 信息架构与页面

沿用现有深色侧栏与卡片式控制台布局，不重做聊天主界面。导航继续包含“运行总览、对话、模型服务、QQ 渠道、MCP 服务、Skills、运行诊断、长期记忆”。本方案重点完善“模型服务、MCP 服务、Skills”三页。

### 4.1 模型服务

Provider 列表卡片展示：

- 名称、类型、启用状态、配置状态、Base URL（脱敏展示）。
- 当前全局默认模型标识。
- 启用模型数量、最近一次测试结果（仅本次运行状态，不假装为持久监控）。
- 操作：查看/编辑、连接测试、启用/停用、设置默认、删除。

Provider 详情/编辑视图分为：

1. **连接配置**：名称、协议类型、Base URL、启用状态、API Key 状态；API Key 只能替换或清除，读取时永不返回明文。
2. **模型列表**：添加/编辑/停用/删除模型；管理显示名、模型标识、工具支持、流式支持、视觉能力、上下文窗口和最大输出 Token。
3. **故障切换**：配置有序备用 Provider，展示实际尝试顺序并阻止自引用、重复项、不可用 Provider。
4. **测试**：选择模型发起短测试；页面展示成功响应或已脱敏错误，不把测试成功等同于长期可用。

删除 Provider 前检查它是否为默认 Provider、Fallback 节点或会话正在引用的 Provider。确认页明确影响；删除后清理对应 Secret 引用和失效的 fallback/default 配置，不删除历史 Agent Run 中已保存的文本记录。

### 4.2 MCP 服务

列表卡片展示：传输方式、启用状态、连接状态、最近错误、最后成功时间、重连次数、Server 版本、能力和已授权数量。空列表显示“尚未配置 MCP Server”及“添加 MCP”操作；不能省略状态行或显示为异常。

新增/编辑流程：

1. 选择 stdio、Streamable HTTP 或 SSE。
2. 填写名称和启动命令/参数，或 URL。
3. 可选设置普通环境变量；Secret 环境变量和 HTTP Header Secret 使用密码输入，仅写入系统密钥存储。
4. 先执行连接测试并展示发现的 Tools、Resources、Prompts，再由用户选择授权范围。
5. 新配置默认禁用或保持工具无授权；用户明确确认后再启用连接与 Agent 工具。

详情分为“连接”“工具授权”“Resources”“Prompts”“诊断”：

- 工具按发现时的名称逐项授权；新增工具默认不自动获得权限。
- Resource 使用显式 URI/前缀 allowlist；读取动作可在详情中发起并限制输出大小。
- Prompt 逐项授权；渲染 Prompt 时显示参数和预览结果，并将返回内容标记为外部内容。
- `legacy_all_tools` 旧配置必须显示醒目提示，并提供迁移到精确白名单的操作；不能悄悄改权限，也不能把空 allowlist 误解为全开。
- 编辑连接配置、Secret、环境变量或权限后，使用配置 revision 触发现有 Runtime 重载；展示“应用中/已生效/失败”，不可只更新数据库却显示成功。

MCP 删除需二次确认，并说明会移除配置和未被其他 Server 引用的密钥；不会卸载用户自行安装的外部程序。

### 4.3 Skills

主列表区分“内置”“用户管理”“未登记本地 Skill”，展示描述、版本/Revision、来源、启用状态、依赖状态、内容是否被本地修改。

用户 Skill 支持：

- 预览安装：本地目录或 HTTPS Git 源；展示来源、Manifest、权限声明、依赖、文件清单和警告，确认后才安装。
- 更新检查：显示当前/目标 Revision、内容哈希变化、增删改文件及 Manifest 变化。
- 应用更新：用户再次确认后调用现有更新服务；失败时保持旧版本可用，并报告原因。
- 启停、移入回收站、查看回收站并恢复；恢复遇同名冲突时拒绝覆盖并给出处理方法。
- 内置 Skill 不可删除；未登记本地目录不得由 UI 直接覆盖或移动。

更新预览和回收站条目要分页或限制数量；页面不能一次加载整个 Skill 内容。安装/更新过程不得执行 Skill 中代码、命令或自动安装依赖。

### 4.4 运行总览

- Provider 默认模型来自服务端实际选择结果，不用列表第一项猜测。
- MCP、Skills 数量为零时明确显示“未配置”，同时保留配置入口。
- 每个模块独立呈现“读取中、正常、未配置、异常、接口不可用”；一个请求失败不能阻止其他卡片更新。
- 全局状态按实际检查结果聚合：运行时未启动、默认模型不可用、已配置 QQ 未连接、已启用 MCP 异常、启用 Skill 依赖缺失等。
- 未配置可选能力不单独把全局状态标为故障；状态文案需说明“未配置”与“连接失败”的差别。
- 事件计数必须标注统计窗口；如只查最近 N 条，不得标成全量积压。

## 5. API 与应用层

遵循“路由校验/序列化，应用服务执行业务规则”的边界。API 命名最终以现有风格为准，预期补充以下操作族：

| 资源 | 预期操作 |
|---|---|
| Provider | 读取详情、更新连接配置、替换/清除凭据、启停、测试、设置默认、设置 fallback |
| Model | 列出、创建、编辑能力参数、启停、删除 |
| MCP | 配置更新、环境变量/Secret 变更、连接测试、能力授权、Resource 读取、Prompt 预览、启停/重连/删除 |
| Skills | 回收站列表、更新预览、应用更新、启停、移入回收站、恢复、安装预览与安装 |
| Dashboard | 返回明确区分配置存在、enabled、运行状态的摘要；允许模块状态独立加载 |

实施前应先检查每个现有应用服务操作是否能保证事务与副作用顺序。密钥更新按“先写新 Secret → 提交新引用 → 删除旧 Secret”处理；若数据库提交失败，删除新 Secret 并保留旧引用。删除 Provider/MCP 后清理引用必须避免误删被其他记录共用的密钥。

对 MCP 的配置变更应继续通过 revision reconciliation 使运行中连接重载；对 Skills 变更应继续 bump Skills revision，交由 Runtime 重载。Web 路由不直接操作 Manager 私有字段。

## 6. 安全要求

1. Web 管理仍只支持本机回环访问；不因新增接口开放 `0.0.0.0` 或局域网管理。
2. 所有写接口验证实际客户端回环地址，并校验 `Host` 与 `Origin/Referer` 的同源关系；不信任 `X-Forwarded-For` 绕过限制。不得添加宽松 CORS。
3. API Key、MCP Secret、QQ Token 不从读取接口返回；更新表单默认空值，成功后清空输入。
4. 日志和 API 错误只返回脱敏信息；不能把 Secret 放入 URL、HTML、前端持久存储或浏览器控制台。
5. MCP/Skill 外部描述、资源与 Prompt 内容均按不可信数据显示，使用文本节点或转义输出，不能作为 HTML 执行。
6. 删除、覆盖更新和未知结果的消息重试需二次确认，并明确不可逆/重复执行风险。
7. 安装 Git Skill 只允许现有服务支持的 HTTPS 来源；UI 不增加任意 URL 拉取、shell 执行或额外本地路径读取能力。

## 7. 错误与状态体验

- 加载状态、空状态、服务端错误和验证错误使用不同文案，不以空数组代表所有失败。
- 失败提示包含可操作原因；成功提示说明是否已写入配置、是否已运行生效。
- Provider 测试失败、MCP 连接失败、Skill 依赖缺失不覆盖此前有效配置。
- 长操作显示进行中状态并禁用重复提交；超时后提供刷新状态，不擅自重放有副作用操作。
- 保存表单采用明确的保存/取消流程；未保存改动离开页面时提醒。
- MCP/Skills 空状态包含直达新增入口；总览对应计数和服务状态采用“未配置”，避免误报健康或故障。

## 8. 分阶段实施

### 阶段 A：服务端管理接口与校验

- 补全 Provider 与模型应用服务操作、默认模型/fallback 读写、Secret 替换。
- 暴露 MCP Secret/环境变量/工具及 Resource/Prompt 授权的安全 API。
- 暴露 Skills 回收站、更新预览与应用更新 API。
- 统一本机写访问、同源检查、错误脱敏与生命周期 revision 更新。

### 阶段 B：Provider 与 MCP 页面

- Provider 详情编辑、模型管理、默认/Fallback 设置、测试状态。
- MCP 添加/编辑向导、Secret 配置、能力发现与 allowlist、运行状态详情。
- 总览空状态和部分加载错误的清晰展示。

### 阶段 C：Skills 生命周期与交付验证

- Skill 更新预览/确认应用、回收站/恢复和本地修改提示。
- 使用真实本地数据完成 Provider→默认模型、MCP→授权工具、Skill→更新/恢复的手动冒烟。
- 更新用户文档，说明本机访问、密钥保护和 CLI 高级入口。

每阶段独立通过测试，不要求引入新的前端框架或数据库迁移。若执行中发现确需 schema 改动，单独说明原因、备份策略和兼容路径后再实施。

## 9. 验收标准

### Provider

- 可添加、查看、编辑、测试、启停、删除 Provider。
- 可添加、编辑、启停、删除模型并设置工具/流式/视觉/上下文/输出能力。
- 可准确显示和修改全局默认模型与有序 fallback。
- API/UI 永不回显已保存 API Key；替换或清除后真实请求使用新配置。
- 删除被默认/fallback 引用的 Provider 时有明确保护或安全清理，不能留下悬空引用。

### MCP

- 三种现有传输均能网页配置、测试、启用、停用、重连和删除。
- stdio 普通/秘密环境变量及 HTTP Header Secret 可创建、替换和清除；所有读取端只显示变量/头名称和设置状态。
- 工具、Resource、Prompt 必须有逐项授权界面；默认权限不扩大；配置变更能在运行中生效。
- Server 故障、未配置、停用和连接中能被区分。

### Skills 与总览

- 本地/Git Skill 可预览安装；用户管理的 Skill 可预览更新、确认应用、移除、恢复。
- 被修改的本地内容、缺少依赖、更新失败和同名冲突都能明确显示；内置 Skill 不可被删除。
- MCP/Skills 空集合显示“未配置”而不是缺行或异常；任何一个 API 失败不会让其他状态仍显示“检查中”。
- 全局总览在有/无 Provider、QQ 连接或断开、MCP/Skills 空集和接口失败等场景都有正确状态。

### 工程验证

- 应用服务单元测试覆盖成功、无效输入、Secret 更新失败回滚、删除依赖关系。
- Web API 测试覆盖状态码、权限边界、Secret 不泄漏和运行时刷新。
- 前端验证加载/空/失败/局部接口不可用场景；手动冒烟完成上述主要用户路径。
- 全量测试、静态检查、构建和 `git diff --check` 通过。

## 10. 交付边界

本方案完成后，星栖拥有适用于单机个人用户的 Provider、MCP、Skills Web 管理台；CLI 保留高级/恢复用途。它仍不是多人远程管理后台，也不提供插件市场、OAuth 登录或第三方扩展自动执行环境。

## 11. 本轮实施记录
