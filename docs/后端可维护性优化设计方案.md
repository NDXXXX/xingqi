# 后端可维护性优化设计方案

## 目标

降低后端高复杂度功能的修改成本和回归风险。本方案覆盖前次审查中的高、中优先级：记忆子系统、CLI 命令入口、QQ OneBot 适配器。保持现有业务行为、API、CLI 命令和数据库格式不变；按功能边界渐进迁移，不做全量重写。

## 范围与分级

| 优先级 | 范围 | 当前主要问题 |
|---|---|---|
| 高 | `application/memories.py`、`core/memory/indexer.py` | 记忆查询、生命周期操作、文件与数据库协调、索引同步及恢复逻辑集中，修改遗忘/恢复功能需要跨文件理解复杂流程。 |
| 中 | `cli/main.py` | 入口同时包含参数定义、命令分派、交互流程和各命令实现；Provider 命令已有独立模块，可沿用该模式。 |
| 中 | `channels/qq/adapter.py` | WebSocket 生命周期与 OneBot 消息解析、组件转换等协议细节共处；纯协议逻辑可独立验证。 |

本轮不处理 `ChatService`、MCP 服务、数据库模型及仓库。它们虽有较多代码，但目前没有足够证据表明拆分能降低维护成本；避免扩大范围。

## 设计原则

1. 按用例或稳定职责拆分，不按行数机械切文件。
2. `MemoryService`、CLI 命令、`QQAdapter` 的外部调用方式保持兼容，先搬实现，再考虑是否调整接口。
3. 文件系统和数据库的一致性恢复属于记忆子系统的关键行为；拆分时保留现有操作顺序和事务边界。
4. QQ 入站策略、去重、恢复、会话和投递已经由适配器/渠道流水线协作处理；本轮只抽离确定的协议转换，不复制已有流水线职责。
5. 每次只迁移一个边界，完成后运行对应现有测试及静态检查，再继续下一步。
6. 不新增框架、服务容器、消息总线或通用插件机制。

## 目标结构

```text
src/zhiyu/
  application/
    memories.py                 # MemoryService 兼容入口与依赖组装
    memory_queries.py           # 记忆查询、搜索、状态与解释
    memory_lifecycle.py         # 新增、编辑、确认、完成、遗忘及文件变更
  core/memory/
    indexer.py                  # 对外稳定入口，导出同步/重建函数
    index_sync.py               # 文件变化检测及增量同步
    index_rebuild.py            # 全量重建、遗忘和生命周期恢复
    index_common.py             # 两种索引流程共用的键、快照和元数据小函数
  cli/
    main.py                     # parser、启动初始化和命令分派
    commands/
      providers.py              # 已存在
      chat.py                   # 单轮/交互聊天命令处理
      memories.py                # 记忆命令处理
      channels.py                # QQ/渠道命令处理
      integrations.py            # MCP、Skills、Embedding 等集成命令
      characters.py              # 角色命令处理
  channels/qq/
    adapter.py                  # WebSocket 生命周期、请求关联和流水线衔接
    protocol.py                 # OneBot 事件解析、消息段转换和文本分段等纯协议逻辑
```

目录只作为目标边界；迁移中如果某个新模块仍很小或没有独立职责，可暂时留在现有文件，不为匹配目录树而制造抽象。

## 详细设计

### 1. 记忆应用服务与索引模块（高优先级）

#### 1.1 应用服务拆分

将 `MemoryService` 的方法按读写用例迁移：

- `MemoryQueryService`：`list`、`search`、`get`、`recall_explain`、`status`、`consolidation_runs`，以及摘要转换逻辑。
- `MemoryLifecycleService`：`add`、`confirm`、`keep`、`edit`、`complete`、`forget`、`plan_forget`、`forget_conversation` 和相关文件/索引更新。
- `MemoryService` 暂时保留现有构造参数和公开方法，作为兼容门面，将调用委托给上述实现。API、CLI、TUI、任务处理器和现有测试不需要同时改导入路径。

读写服务共享 `session_factory`、`MemoryStore` 和必要的仓库依赖；不要把 ORM Session 长期保存在服务实例中。数据库事务仍由一次具体用例创建、提交或回滚。

摘要数据结构 `MemorySummary` 继续只定义一份。只在确有重复时提取共享转换函数，避免查询服务与生命周期服务各自实现不同的摘要字段。

#### 1.2 文件变更和恢复边界

`forget_conversation`、删除/编辑和核心记忆变更涉及 Markdown 文件、SQLite 行、来源关系、嵌入和 `MemoryMutation` 恢复记录。迁移时将完整用例作为整体移动，不在多个新模块中拆开事务步骤。

记忆生命周期服务负责业务意图，例如哪些记录应删除、保留或标记完成；索引重建负责从文件和持久化变更记录恢复数据库状态。两者通过已有 `MemoryMutation` 数据表达恢复上下文，不增加第二套恢复状态。

#### 1.3 索引模块拆分

- `index_sync.py`：承载 `sync_changed_index` 及增量文件变更处理。
- `index_rebuild.py`：承载 `rebuild_index`、旧数据迁移、缺失条目修复、遗忘墓碑和未完成变更恢复。
- `index_common.py`：只放同步与重建都使用的纯辅助逻辑，例如稳定 entry key、索引快照写入和安全元数据解析。
- `indexer.py` 继续导出 `sync_changed_index`、`rebuild_index`，供现有应用服务、运行时和测试沿用原导入路径。

### 2. CLI 命令入口（中优先级）

保留 `cli/main.py` 中 argparse 的命令树，避免分散参数定义导致命令结构难以理解。将命令执行函数迁至 `cli/commands/`，由 `run()` 根据解析后的命令调用对应 handler。

- `_chat_line`、`_chat_tui`、`_send` 迁入 `commands/chat.py`；终端输出格式化辅助函数跟随实际调用方迁移，不另外搭建通用渲染层。
- `_memory`、`_print_memories` 迁入 `commands/memories.py`。
- `_qq`、`_qq_doctor` 迁入 `commands/channels.py`；`_qq_listen` 若仅被 QQ 命令调用，也一并迁移。
- `_mcp`、`_skills`、`_embedding` 迁入 `commands/integrations.py`。若迁移后文件形成明显不同的独立维护单元，再拆分，不预先拆成大量单函数模块。
- `_character` 迁入 `commands/characters.py`。
- Provider handler 保持在现有 `commands/providers.py`，统一 dispatcher 调用约定。

Parser 仍由 `main.py` 定义，handler 只接收已解析参数并执行命令。共用的启动初始化与错误处理留在入口，不让 command 模块互相导入。

### 3. QQ OneBot 适配器（中优先级）

新增 `channels/qq/protocol.py`，先迁移不依赖适配器状态的协议处理：

- 解码/识别 OneBot 事件结构。
- 提取消息文本、@ 信息和统一消息组件。
- 将统一消息组件编码为 OneBot 消息段。
- 长消息切分及 loopback 地址判断等纯输入输出逻辑。

`QQAdapter` 保留 WebSocket 服务启动/关闭、鉴权、echo 请求关联、pending future、并发限制、事件流水线接入、会话锁、恢复和投递状态。`_is_allowed` 等带适配器配置或业务状态的行为也先留在适配器中。

如果现有测试或内部调用直接依赖适配器的私有纯函数，可在迁移阶段保留薄委托方法，避免同次修改扩大测试和调用方变更范围；稳定后再按实际使用情况决定是否删除。

## 实施阶段

### 阶段一：拆分记忆服务实现

1. 迁移查询用例到 `memory_queries.py`。
2. 迁移生命周期用例到 `memory_lifecycle.py`，保持文件 mutation 与数据库事务顺序。
3. 保留 `MemoryService` 兼容入口和构造签名。
4. 验证 Web API、CLI/TUI、记忆任务及记忆生命周期测试。

### 阶段二：拆分索引同步与重建

1. 迁移增量同步逻辑，确保导入 `zhiyu.core.memory.indexer.sync_changed_index` 不变。
2. 迁移全量重建和恢复逻辑，确保 `rebuild_index` 原导入路径不变。
3. 提取少量重复的纯辅助函数到 `index_common.py`。
4. 验证增量同步、重建幂等、文件 mutation 恢复、身份隔离及遗忘恢复。

### 阶段三：迁移 CLI handlers

1. 先迁移相对独立的记忆、角色和渠道命令。
2. 再迁移聊天与集成命令。
3. 保留 parser、命令名、参数、输出和退出码。
4. 验证 CLI 命令、渲染与 TUI 测试。

### 阶段四：抽离 QQ 协议函数

1. 迁移纯消息解析和编码函数到 `qq/protocol.py`。
2. 适配器调用协议函数，保留所有连接和会话状态管理。
3. 验证 QQ 入站/出站组件、权限、去重、恢复及投递行为。

## 验收标准

### 行为兼容

- Web API 路径、请求/响应字段和错误语义不变。
- CLI 命令名、参数、交互提示、输出和退出状态不变。
- QQ OneBot 的鉴权、收发、权限过滤、去重、组件转换和恢复行为不变。
- 记忆文件格式、数据库 schema、索引键、事务顺序和崩溃恢复语义不变。

### 结构清晰

- `MemoryService` 的查询逻辑与生命周期写操作可在不同模块中独立定位，兼容入口不再承载全部实现。
- 增量索引与全量重建分属不同模块，原 `indexer` 导入路径仍有效。
- `cli/main.py` 主要保留 parser、初始化、dispatch 和进程入口；Provider 以外的主要命令实现位于 command 模块。
- `QQAdapter` 不再直接包含纯 OneBot 消息解析/编码实现；连接和有状态流程仍集中于适配器及现有流水线。
- 不新增循环导入；业务逻辑只存在一份，不保留双实现。

### 回归验证

按阶段运行现有测试，至少覆盖：

- 记忆：`test_memory_lifecycle.py`、`test_memory_vaults.py`、`test_memory_jobs.py`、`test_deep_recall.py`。
- CLI：`test_cli.py`、`test_cli_render.py`、`test_cli_tui.py`。
- QQ：`test_qq_reverse.py`、`test_channel_pipeline.py`、`test_channels.py`。
- 完成全部阶段后运行项目完整测试套件及格式/静态检查。

## 风险与处理

| 风险 | 处理方式 |
|---|---|
| 记忆文件与数据库迁移顺序被拆坏，造成重启后状态不一致 | 整个用例整体搬移；先迁移再做逻辑调整；重点覆盖 mutation 中断与恢复测试。 |
| `MemoryService` 的构造签名或调用方法改变，牵连 API/CLI/TUI | 保留现有兼容门面，分批更新调用方仅作为后续可选工作。 |
| 索引模块互相导入导致循环依赖 | 让公共辅助模块只依赖存储模型和纯函数；入口模块只做导出，不承担共享实现。 |
| CLI 参数定义与 handler 迁移不同步 | parser 保持集中；先搬 handler，不改命令协议。 |
| 抽离 QQ 纯函数时改变协议边界或事件时序 | 只迁移纯转换；有状态行为继续留在适配器和现有流水线。 |
| 一次拆分多个子系统导致定位困难 | 分阶段提交/验证；每阶段只改一个子系统，发现行为差异先修复再进入下一阶段。 |

## 本轮不做

- 不重写记忆算法、索引策略或记忆文件格式。
- 不改数据库表结构、迁移记录和公开 API。
- 不重构 `ChatService`、MCP 服务、数据库模型或 repository。
- 不引入 command 自动发现、插件注册、依赖注入框架或新的抽象层。
- 不借整理之机删除与本次迁移无关的代码。

## 实施结果

- 阶段一、二已完成：`MemoryService` 保留原构造与公开调用入口，查询和生命周期操作分别迁入独立模块；`indexer` 保留原导入路径，增量同步与全量重建分别实现。
- 阶段三已完成：CLI 命令处理迁入 `cli/commands/`，`main.py` 保留 parser、启动准备、分派和进程入口；TUI 改为依赖聊天命令模块。
- 阶段四已完成：OneBot 纯解析与消息转换迁入 `channels/qq/protocol.py`，`QQAdapter` 保留状态和连接流程。
- 为适配新的模块所有权，既有 CLI 与记忆恢复测试中的 patch 目标改为对应的 handler/lifecycle 对象。
- 验证：完整后端测试套件通过（225 passed）；Python 3.12 `compileall` 和 `git diff --check` 通过。
