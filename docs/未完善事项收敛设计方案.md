# 未完善事项收敛设计方案

> 版本：v1.0  
> 日期：2026-10-07  
> 状态：核心自动化与部分浏览器验收已完成；真实第三方服务验收待用户环境
> 范围：补齐 Web UI 验收、CLI/TUI/QQ 运行取消、长期记忆性能与诊断、MCP/Skills 真实环境验证。

## 1. 背景与目标

> 本节和第 2 节按 2026-10-08 当前状态更新；第 4–10 节保留为阶段实施要求，原始基线以各节实施记录为准。

本方案早期基线中的若干欠项已在后续实施记录中完成：CLI/TUI/QQ 的按会话停止、记忆索引状态诊断、语义摘要回退、记忆召回基准与热点优化，以及 Web 的部分隔离浏览器验收。当前仍需完成 Web 完整可用性场景与真实模型聊天取消验收、更大规模记忆召回评估，以及真实第三方 MCP、系统密钥存储和用户 Git 来源的环境验收。后者依赖用户机器和账号，未提供环境时应保持“未验证”状态。

本方案把这些欠项拆成可独立交付的阶段。完成后应满足：

1. Web 的主要管理和聊天路径有可复现的浏览器验收记录。
2. CLI/TUI/QQ 均可停止当前会话中的 Agent Run；停止结果和部分回复状态清楚，不误取消其他会话。
3. 记忆系统有 1,000 和 10,000 条数据基准结果；索引同步失败能从诊断入口发现；会话摘要可在满足安全约束后升级为语义摘要。
4. MCP/Skills 有自动化协议覆盖和不含密钥的真实环境验收流程，能区分产品缺陷与外部服务/凭据配置问题。

## 2. 当前基线与约束

- Web UI 已迁移至 React；隔离数据目录下已验收导航、部分管理流程、MCP 与本地 Skill 生命周期。真实模型聊天取消、键盘焦点和未保存离开等完整场景仍需核对。
- `ActiveRunManager` 已记录内部 Conversation 与外部渠道 Session；TUI 和 QQ 主人均有按会话 `/stop`。自动化测试覆盖不同会话隔离；Web 取消路径也有应用层覆盖。
- 记忆差量同步、摘要游标、诊断页索引状态和语义摘要失败回退已实现。n-gram 特征预计算后，10,000 条合成数据召回 p95 为 325.76 ms；仍全量扫描候选，更大规模需继续评估。
- MCP/Skills 的协议测试使用本地测试服务。真实第三方 MCP、Keychain、用户 Git 源依赖具体机器和账号，不能作为 CI 的必需外部依赖。
- 不改变本机 API 的 Host、Origin、回环地址和写请求标记检查；不降低 QQ 主人权限、群聊白名单、@ 规则、Token 和事件去重要求；不把 Secret 写入日志或验收材料。
- 真实浏览器验收使用隔离的 `ZHIYU_DATA_DIR`。不对用户真实 `~/.zhiyu` 数据执行破坏性测试，不在仓库提交真实凭据、QQ 消息或个人数据。

## 3. 范围与非目标

### 本方案范围

- Web 核心流程的浏览器验收；只做必要的缺陷修复和页面编排拆分。
- 面向当前会话的 Agent Run 取消能力及 CLI/TUI/QQ 命令接入。
- 记忆基准脚本、结果记录、索引状态诊断及可选的语义摘要实现。
- MCP/Skills 自动化与真实环境验收的分层、记录模板和故障定位要求。

### 本方案不包含

- QQ 多账号并行、官方 QQ Bot、语音识别/合成、MCP/Skills 市场、ZIP 安装或依赖自动安装。这些是产品能力扩展，另立方案和验收。
- 新增远程管理能力、身份认证模型、消息队列或向量数据库。
- 将用户真实服务凭据或真实第三方服务纳入公共 CI。
- 为模块化而重写整个前端；拆分范围限定为 `app.tsx` 中已明确独立的页面/请求职责。

## 4. 阶段 A：Web UI 浏览器验收与收敛

### 4.1 验收环境

使用隔离数据目录启动 `zhiyu serve`，准备可重复的数据：至少一个 Provider 配置、一个测试 MCP Server、一个测试 Skill、一个记忆条目和两个对话 Session。Provider 请求使用可控测试端点或开发环境的专用账号，不复用生产密钥。MCP 授权测试优先使用仓库内可控的本地测试 Server。

### 4.2 浏览器场景

1. 刷新、前进/后退和深链接：总览及指定会话路由保持正确。
2. MCP：添加测试 Server、发现能力、授权/撤销工具、刷新后状态一致；Secret 不回显。
3. Provider：编辑配置、测试连接、设置默认模型；错误状态不误报为“未配置”。
4. Skills：预览安装、确认安装、预览更新、取消更新、回收和恢复；失败时旧版本仍可用。
5. 记忆：搜索、查看来源、确认/纠正/删除操作及错误反馈。
6. 聊天：发送、切换 Session、新建 Session、停止生成；迟到的 SSE 事件不得改写当前 Session。
7. 可用性：窄屏导航、键盘焦点顺序、弹窗关闭与焦点恢复、未保存离开提醒。
8. 安全：检查浏览器存储、URL、控制台和网络响应，确认没有 Secret 明文；外部 MCP/Skill 文本按纯文本展示。

浏览器验收记录版本、操作路径、预期/实际结果、失败截图或脱敏日志、所用数据目录类型和环境信息。不得记录 Secret、QQ 号、真实聊天内容或私有 Git 地址。

### 4.3 前端拆分

浏览器验收发现的行为问题优先修复。随后只将 `app.tsx` 中清晰独立的页面编排和管理操作按现有 `web/src/pages/` 结构拆分；Shell、导航和跨页面聊天生命周期仍由应用入口负责。暂不引入全局状态管理库、路由库或额外请求框架。

### 4.4 完成条件

- 上述浏览器场景全部通过；失败项有修复记录或明确阻塞原因。
- 页面切换和聊天取消没有跨 Session 的状态污染。
- Secret 不出现在 DOM、浏览器存储、URL、控制台或 API 读取响应中。
- `app.tsx` 只保留 Shell、导航和跨页面编排；页面专属操作位于相应页面模块。
- 前端 typecheck、test、build 和相关 Python Web API 测试通过。

## 5. 阶段 B：CLI/TUI/QQ 停止当前回复

### 5.1 统一语义

取消目标是一个正在运行的 Agent Run。入口必须将取消范围限定为当前入口选中的会话，不按全局“最新任务”猜测，也不取消其他 QQ 会话或 TUI/Web 会话。

取消后：

- Agent Run 状态记录为 `cancelled`。
- 已展示的部分回复可以保留，但不能保存成完整成功回复，也不能触发成功回复的记忆提取任务。
- 用户收到明确的“已停止”状态；没有运行任务时返回明确提示，不当成错误或成功。
- 取消正在等待 Provider/MCP 的任务时应尽快结束；清理会话锁、活动任务登记和临时资源。

### 5.2 Application 能力

在 Application 层增加或扩展一个按会话取消的用例，入口传入内部 `conversation_id`。`ActiveRunManager` 维护运行中的 Run 与会话的对应关系，并只取消匹配的活动 Run。若同一会话按现有规则最多只有一个活动 Run，则该约束应由服务层保证并测试。

禁止 CLI、TUI 或 QQ Adapter 直接操作全局任务字典。Web 现有 run ID 取消 API 保持兼容；如内部统一到会话取消，用例仍需确认 run ID 属于目标会话。

### 5.3 CLI 与 TUI

- 单条 CLI 聊天保留 Ctrl-C 取消行为，输出明确停止结果并以正常取消状态退出。
- TUI 增加 `/stop`，只取消当前会话的活动 Run；无活动任务时显示“当前没有运行中的回复”。
- TUI 执行生成时保留 Run ID/会话 ID，停止后恢复输入框、状态栏和焦点；再次发送不会复用旧 Run 的事件或回复缓冲。
- `/help` 补充 `/stop`。不新增独立后台守护进程或复杂任务列表。

### 5.4 QQ

- 仅主人消息可以触发 `/stop`；群聊仍遵循现有群白名单和 @ 规则。
- `/stop` 只停止当前 QQ 账号、当前私聊/群会话的活动 Run，不影响同账号其他会话。
- 不把控制命令发送给模型，不将其持久化为普通用户聊天内容；记录必要的运行审计状态但不记录 Secret。
- 如果当前 `ChatService`/Pipeline 无法在安全边界内识别命令，先在 Application 用例中实现命令分派，不在 OneBot Adapter 中直接取消 Agent。

### 5.5 完成条件

- CLI Ctrl-C、TUI `/stop`、QQ `/stop` 均能结束活动 Run，并区分正常完成、模型失败和用户取消。
- 多会话并发时只取消命中的 Run；非主人或不符合群策略的命令不产生取消副作用。
- 取消后可立即继续发送消息，运行锁、任务注册和 Agent Run 状态一致。
- 覆盖 Provider 等待、工具调用、生成流式输出和任务已结束等边界测试。

## 6. 阶段 C：记忆性能、诊断和语义摘要

### 6.1 可复现基准

新增独立基准命令或脚本，使用临时数据目录和固定随机种子生成 1,000、10,000 条记忆及多轮长会话数据。至少记录：

- 召回命中、错误注入、冲突纠正和遗忘场景的结果。
- 每轮解析的记忆文件数、数据库候选数、会话历史读取行数。
- 聊天准备阶段、索引同步和召回的 p50/p95 耗时及峰值内存。
- 冷启动全量恢复与普通未变更轮次的耗时。

结果写入本地可生成的 JSON/Markdown 报告，不提交机器专属绝对路径或用户数据。与旧实现比较时固定数据、随机种子、Python/SQLite 版本和重复次数。验收先确认普通未变更轮次不重复解析未变更文件，长会话读取边界稳定，p95 不劣于记录的基线；若指标退化，必须定位原因后再宣称通过，不先设没有测量依据的绝对毫秒目标。

### 6.2 stale/failed 诊断

- 将索引同步状态及最近一次成功时间、最近错误摘要暴露给现有 Doctor/Diagnostics 页面。
- 状态至少区分 `ready`、`stale`、`indexing`、`failed`；不能在重建失败后继续显示 ready。
- 索引不可用时沿用上一次有效索引或现有安全降级路径；聊天不因诊断状态不可读而失败。
- 诊断错误需脱敏，不暴露记忆正文、绝对文件路径或 Secret。
- 页面提供可操作说明和现有修复入口；若全量重建属于破坏性/耗时操作，必须明确确认后执行。

优先复用已有状态与 Doctor/Diagnostics 服务。只有代码证明确实无法持久表达状态时，才新增迁移；迁移必须支持旧数据库升级，不要求删除用户数据库。

### 6.3 语义摘要

在已有摘要游标和边界正确性基础上，把模型摘要作为可回退的摘要生成方式：

1. 仅跨过既有压缩阈值时生成摘要，不在每轮对完整历史重复总结。
2. 提示词要求保留未完成请求、用户纠正、姓名/日期/编号等精确事实和来源边界。
3. 验证摘要长度、必需信息和来源约束；超限、空结果、模型失败或校验失败时使用现有确定性摘要。
4. 摘要调用及费用/延迟必须可观测；取消聊天时不得提交半成品检查点。
5. 语义摘要不得把不同 Session 的原始 transcript 合并，也不得越过身份隔离和记忆 mutation/recovery 机制。

先用固定会话样例比较语义摘要与确定性摘要的事实保留、遗漏和延迟，再决定默认启用条件。不能以“摘要更自然”代替事实回归。

### 6.4 完成条件

- 基准能在隔离环境重复运行，并产出可比较报告。
- 1,000/10,000 条数据均通过正确性场景；性能结果有基线和明确结论。
- 人工制造索引同步失败后，诊断显示 stale/failed 与可操作原因；恢复后状态回到 ready。
- 语义摘要失败会安全回退；事实回归通过且不破坏会话边界。
- 记忆正文、身份隔离、索引恢复与现有文件/SQLite 一致性测试继续通过。

## 7. 阶段 D：MCP/Skills 真实环境验证

### 7.1 自动化与真实验证分层

- CI 继续覆盖本地 MCP SDK Server 的 stdio、Streamable HTTP、SSE、Tools、Resources、Prompts、连接失败与恢复行为。
- Skills 自动化覆盖本地目录和本地 Git 仓库的安装、预览、更新、回收与恢复，不访问个人私有仓库。
- 真实第三方服务验证采用手工验收清单，由用户环境运行；不把真实网络、真实 Keychain 或真实账号作为 CI 必需条件。

### 7.2 MCP 验收步骤

在隔离数据目录中逐项验证：

1. 用户选定的可信 stdio 或 HTTP MCP Server 能连接并显示能力。
2. 工具默认无授权；明确授权后才能供 Agent 调用，撤销授权后不再调用。
3. Resource/Prompt 在允许范围内可读取/渲染；异常或过大响应有清晰错误。
4. Secret 通过系统密钥存储或批准的环境变量引用提供；读取 API、日志和诊断输出不泄露值。
5. 停用、重连、配置变更和 Runtime 重启后状态符合预期；单个 Server 故障不影响聊天或其他 Server。

### 7.3 Skills 验收步骤

使用用户有权访问的本地或 HTTPS Git 仓库：

1. 预览来源、Manifest、文件清单和警告后再安装。
2. 更新预览正确显示增删改及 Manifest 变化；用户取消时不修改当前版本。
3. 应用更新失败时旧版本仍可用；回收后能恢复且同名冲突不会覆盖现有目录。
4. 全流程不执行 Skill 脚本、不自动安装依赖，日志不泄露私有凭据。

### 7.4 记录与完成条件

验收记录只保存服务类型/传输方式、客户端与服务端版本、测试日期、通过/失败步骤和脱敏错误类别。真实服务名称、URL、仓库地址和账号信息默认匿名化。未能取得真实服务/凭据时，记录为“环境未提供，待用户环境验证”，不能标记为产品缺陷，也不能宣称真实集成已通过。

完成条件：自动化协议测试在 CI 通过；至少完成一个用户可访问的真实 MCP Server 和一个 Git Skill 来源的手动验收，或在交付记录中明确环境阻塞与未验证边界。

## 8. 实施顺序

1. **阶段 B 取消能力**：行为边界明确、影响多入口运行，先建立 Application 用例和测试，再接 TUI/CLI/QQ。
2. **阶段 A Web 验收**：在隔离数据上操作完整路径，根据结果修复并有限拆分前端。
3. **阶段 C 记忆诊断与基准**：先测量和补诊断，再决定是否启用语义摘要。
4. **阶段 D MCP/Skills 验收**：自动化回归与真实环境手工清单并行准备，最后记录环境验证状态。

各阶段不相互依赖，可分开提交；不因整理文档而顺手改写相邻模块。

## 9. 总体交付验收

- Python、Web 前端现有测试和构建通过；新增行为有针对性测试。
- CI 不依赖真实第三方凭据；用户环境验收有独立、脱敏的记录。
- Web 浏览器清单、取消能力场景、记忆基准报告和 MCP/Skills 验收记录均已交付。
- `README.md` 仅在实际能力变化后更新；当前多账号、语音转写、市场等产品限制保持在其独立范围内。
- 所有数据库变化均通过 Alembic Migration；不要求用户删除数据库或清空 `~/.zhiyu`。
